# 数据库

正式开发数据库为 MySQL 8，字符集 utf8mb4。v0.3 包含账号、题材、作品、章节、审核记录、书架和阅读进度七张业务表。

建表脚本唯一来源为后端 [db/migration](../backend/src/main/resources/db/migration/)：V1 创建账号表；V2 新增 `novel_category`、`novel`、`chapter` 和 `content_review`，并初始化六种题材；V3 新增 `bookshelf` 和 `reading_progress`。后端启动时由 Flyway 按版本执行，成功后记录到 `flyway_schema_history`；已有迁移不要修改，结构变化增加新版本脚本。

`app_user` 保存账号、密码散列、昵称、简介、角色、启用状态、令牌版本与时间。账号统一转小写，唯一索引保证并发注册也不能产生重复账号。角色限制为 READER / AUTHOR / ADMIN。

本地启动脚本创建独立 MySQL 实例与数据库，不访问既有数据库。测试代码使用隔离 H2 内存库，不能替代实际 MySQL 验证。数据库数据目录、连接凭据与日志均保存在被忽略的 `.runtime/`。

## 内容数据关系

- 一个作者对应多部作品，一部作品对应多个章节；作品引用一个题材。
- `novel` 和 `chapter` 分别保存草稿与 `public_*` 公开快照；审核通过时在同一事务内更新快照和审核记录。
- `version` 配合行锁检查过期修改；章节写操作统一先锁父作品，再锁章节。
- 草稿章节序号与公开章节序号分别设唯一索引。软删除保留章节 ID 与审核关联，同时将两个序号置空释放位置。
- `content_review` 保存处理对象、送审版本、处理人、原因与内容快照；页面返回摘要，普通读者接口不返回私有审核数据。

结构与接口说明见[内容设计](../docs/作品章节审核设计与接口.md)。V3 使用用户与作品联合主键存储书架及独立的阅读记录；移出收藏不删除进度。版本号与正文指纹防止并发覆盖和位置失效，见[书架进度设计](../docs/书架与阅读进度设计.md)。本版本不创建评论或统计表，不生成虚假的阅读量。

## V4 评论与点赞

新增 reader_comment（小说/章节评论、根评论及回复关联、删除审计）与 comment_like（评论/账号联合主键）。升级不清空原有数据，完整规则见[评论互动设计](../docs/评论互动设计与接口.md)。同作品写入按固定顺序加锁，评论写入采用 READ_COMMITTED；创建与删除时间由后端明确写入 UTC。
