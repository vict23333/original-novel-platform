# 原创小说读写平台 · 正式工程

课程与毕设共用的唯一业务工程。v0.4 在账号、作品、章节、审核、阅读与书架进度基础上，新增作品/章节评论、回复、点赞及管理员评论管理。作者保存草稿后单独提交作品与章节；管理员通过后读者才能获取对应公开内容。已发布内容的修订在通过前保留旧版，违规下架会拦截公开访问。

需要 Java 21、Maven 3.9、MySQL 8.0、Node 20.19+（20 系列）或 22.12+、npm。实际验证使用 Node 24；Node 18 无法运行本项目 Vite。脚本不会修改全局工具配置。

## Windows 本地运行

在本目录打开 PowerShell：

```powershell
./scripts/build.ps1
./scripts/dev.ps1 -Action Start
./scripts/dev.ps1 -Action Status
./scripts/dev.ps1 -Action Stop
```

build 运行后端测试、生成 jar、按锁文件安装前端依赖、执行前端测试并构建。首次 Start 创建独立 MySQL 数据目录、生成随机数据库/JWT/管理员凭据、执行迁移并启动前后端；再次启动保留数据。Stop 只处理该脚本记录且进程身份匹配的程序，数据库正常关闭。端口占用时不会停止其他程序。

服务正在运行时，先 Stop 再 build，避免 Windows 锁定正在使用的依赖或 jar 文件；脚本会提前检查并提示，不在运行中的工程内重装依赖。

默认 Node 太旧时，build 和 dev 脚本均可用 `-NodeExe` 指定已安装的新版 node.exe；dev 可用 `-MySqlBin` 指定 MySQL bin 目录。首次启动选定的工具路径只记录在 `.runtime/settings.local.json`，之后自动复用。

| 服务 | 开发地址 |
| --- | --- |
| 正式平台页面 | http://127.0.0.1:5173 |
| 后端健康检查 | http://127.0.0.1:8081/api/health |
| 独立 MySQL | 127.0.0.1:13406，数据库 novel_platform |

服务只绑定本机。`.runtime/` 内含数据库、私密配置和日志，不得提交 Git；不要创建 `.runtime/nonexistent-socket-dir`，该路径用于本机 Java NIO 的 TCP 回退参数。

读者和作者在页面自行注册。管理员由本机配置初始化，可查看 `.runtime/settings.local.json` 的 adminUsername/adminPassword 后从普通登录页进入；不要分享此配置文件。

## 手动配置与启动

不使用脚本时先创建空 MySQL 数据库，并设置当前 shell 环境变量：

| 变量 | 用途 |
| --- | --- |
| DB_URL | JDBC MySQL URL，默认本机 13406/novel_platform、UTC |
| DB_USERNAME / DB_PASSWORD | 数据库身份，启动迁移需有本库建表权限 |
| JWT_SECRET | 至少 32 个随机字节的 Base64 编码，无默认值 |
| ADMIN_USERNAME / ADMIN_PASSWORD | 可选的首次管理员初始化，不重置已有账号 |
| SERVER_ADDRESS / SERVER_PORT | 默认 127.0.0.1:8081 |

在 backend 执行 `mvn spring-boot:run`；在 frontend 执行 `npm ci`、`npm run dev`。前端不接收数据库密码或 JWT 签名密钥。Vite 默认代理到后端 8081，改后端端口需同步改代理。

## 验收顺序

1. 从首页注册读者并登录，应回到首页；主动点击个人中心，修改昵称和简介，刷新确认已保存。
2. 直接登录作者应进入工作台，管理员进入审核后台；退出后访问书架应跳转登录，登录后回到书架。从书籍详情或阅读页点击登录，再切换注册与登录，成功后仍回到原书页。已登录时访问登录页不再出现表单。
3. 作者进入工作台，新建作品并选择题材、填写简介、保存草稿，提交作品审核；再新建章节、保存正文、提交章节审核。
4. 管理员从管理后台分别选择小说作品与章节内容，查看正文后审核通过。读者与作者不能调用审核接口，公开注册 ADMIN 必须失败。
5. 从首页书库按书名、作者昵称或题材检索，进入详情和章节目录，阅读正文并切换章节、字号、背景；刷新后阅读设置保留。
6. 作者修订已发布章节并保存：读者仍看到旧版；新稿提交并通过审核后才替换。审核期间禁止修改、删除，冲突时先保留输入再重新读取。
7. 管理员在“已有公开版本”中填写原因并下架，读者不能从目录或章节直链访问；作者重新送审并通过后恢复。
8. 在详情或阅读页加入书架，多次加入不重复。登录后阅读较长章节，滚动并等待“已保存到第 N 段”，从书架继续阅读应恢复到段落。
9. 移出书架，收藏条目消失但进度保留；换账号看不到前一个账号的书架和进度。多个页面冲突时按提示明确选择是否保存当前位置。
10. 在作品详情和章末分别发表评论、回复、点赞与取消，刷新后仍保留。删除自己的根评论后正文隐藏、回复仍在；其他账号不能删除本人评论。
11. 管理员从审核页进入评论管理，按关键词或作品编号检索，填写原因删除；前台刷新只显示删除占位，后台可查处理时间与原因。
12. 停止并重启服务，再登录，资料、作品、书架和阅读进度仍在。Stop 会等待进程退出，再 Start，避免数据库仍在关闭。

升级旧的 v0.1—v0.3 实例时，先 Stop、build，再 Start。Flyway 自动执行尚未应用的 V2、V3、V4，保留已有账号与内容，不要删除 `.runtime/`。脚本启动的后端产物为 `novel-platform-0.4.0.jar`。

当前固定提供六种题材，尚无分类标签维护界面。榜单、作品统计、AI 调用、用户管理尚未实现；字号背景只保存在当前浏览器，登录后的阅读进度保存在数据库。本地演示作品来自测试时创建的合成内容，初始化迁移不会向新数据库自动写入演示账号或小说。

测试命令：backend 执行 `mvn test`（隔离 H2 内存数据库），frontend 执行 `npm test`（登录导航场景）与 `npm run build`。实际 MySQL 与浏览器验证结果见验证记录。业务源码按本项目需求独立编写，未复制实验项目业务代码；第三方依赖遵循各自许可证。

## 可选的演示书库

本地可导入 18 部原创演示短篇、36 章，六种题材各三部，配六张有明确 CC0 来源的题材插画封面。在本目录执行 `python scripts/seed-demo.py`，需要后端已启动；重复执行不新增重复记录。简介明确标为演示，演示作者昵称附“（演示）”。不会清空原有数据，也不会生成虚假阅读量或收藏量。

内容、导入恢复规则与查看方式见 [演示数据说明](database/演示数据说明.md)，图片来源见 [封面记录](frontend/public/covers/README.md)。脚本生成的随机演示作者密码只保存在 `.runtime/demo-catalog-state.local.json`。新增内容属于演示作者，在首页书库可见，不自动归入当前登录作者的作品列表。
