# v0.9 管理记录检索验证记录

验证日期：2026-09-27。本轮补齐操作记录的筛选和历史分页，属于既有用户、分类标签管理的维护功能，无数据库迁移。

## 实现与接口

管理后台 `/admin/audits` 支持处理原因关键词、对象类型、操作类型和对象编号组合查询。默认每页 12 条，支持翻页及直接跳页，按记录编号倒序。筛选修改后点击查询生效，查询和重置回到第一页；翻页沿用已应用条件，刷新保留当前页。失败保留上次结果并提示重试。

新增 `GET /api/admin/audits/search`，返回 `items/page/size/total`：

| 参数 | 规则 |
| --- | --- |
| keyword | 原因文本的字面子串，去除首尾空白，最多 100 字符 |
| type | 空值、USER、NOVEL、categories、tags |
| action | 空值、PROFILE、ENABLE、DISABLE、CREATE、RENAME、DELETE、CLASSIFY |
| targetId | 可选正整数；建议搭配对象类型，避免不同对象编号重合 |
| page / size | 页码 1—100000，每页 1—50 条；默认 1 / 12 |

非法输入返回 400；游客 401；读者、作者 403。查询参数绑定，不拼接输入为 SQL。一次响应的列表和总数使用只读、可重复读事务；多个分页请求之间若新增记录，页内容仍可能移动，刷新可获取最新记录。保留旧 `/api/admin/audits` 最近 50 条数组接口，兼容此前调用。

记录仅查询，不开放修改或删除；作品审核和评论处理仍在各自管理页查看。大规模审计数据的查询性能和游标分页不在本轮验收范围。

- Tabbit 浏览器：未登录访问后台后登录回跳、分页、未提交筛选不影响翻页、组合筛选、对象编号查询、空结果、重置、网络失败保留旧结果与重试均通过。
