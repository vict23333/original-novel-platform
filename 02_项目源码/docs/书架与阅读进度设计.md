# 书架与阅读进度 · v0.3

本轮实现 FR-04 书架收藏，并补齐 FR-03 的账号阅读进度。功能入口为作品详情、阅读页和导航中的“我的书架”，继续使用同一个正式工程。

## 业务规则

- 登录用户可收藏已公开、未下架作品；作者和管理员也可使用自己的书架。游客可以阅读，但不能访问私有书架和进度接口。
- 同一用户与作品只保留一条收藏记录，重复加入不重复计数；移出幂等，且不会删除阅读进度。下架作品仍可从书架移除。
- 阅读记录独立于收藏。每部作品按账号保存最近一次成功写入的章节与段落，允许主动回读较早章节或段落，不采用“只保存最大页码”。
- 段落以正文中的空行分隔，保存从 0 开始的索引，界面按第 1 段开始显示；连续空行、CRLF 与 LF 按一致规则处理。恢复到段落开头，不承诺逐字、像素位置完全一致。
- 已保存章节不可读时，保留原记录并提示，从首个可读章节开始；整部作品下架或没有可读章节时不提供继续阅读链接。公开接口依旧校验作品和章节可见性，不能通过进度访问草稿。
- 正文审核修订后，旧段落索引可能失效，恢复时改为本章开头并提示。公开正文 SHA-256 指纹随阅读响应返回；保存时必须匹配当前正文，旧页面不能把旧正文位置写进新版。
- 同一作品的进度使用递增 `version`。多标签页或设备发生冲突时返回 409，暂停该页面自动保存；用户可明确点击“保存当前位置”读取最新版本后再保存。不会自动覆盖另一页面的更新。

## 数据与实现

[V3 迁移](../backend/src/main/resources/db/migration/V3__bookshelf_reading_progress.sql) 新增 `bookshelf` 与 `reading_progress`，不修改已应用的 V1、V2，不清空账号、作品和审核数据。

| 表 | 关键字段 | 约束 |
| --- | --- | --- |
| bookshelf | user_id、novel_id、added_at | 用户与作品的联合主键；用户、作品外键 |
| reading_progress | user_id、novel_id、chapter_id、paragraph_index、content_revision、version、updated_at | 用户与作品的联合主键；账号、作品、章节外键；段落非负、版本为正 |

写操作先锁当前账号行，同一用户的首次插入与后续更新都被串行化。加入书架及保存进度还会锁作品；保存进度按作品后章节的顺序锁定，校验可见性、所属作品、正文指纹、段落边界及进度版本。所有用户 ID 仅从已认证身份取得，请求中不接受目标用户字段。

源码入口为 [ReadingController](../backend/src/main/java/com/novelplatform/reading/ReadingController.java)、[ReadingService](../backend/src/main/java/com/novelplatform/reading/ReadingService.java)、[ReadingMapper](../backend/src/main/java/com/novelplatform/reading/ReadingMapper.java)。`ReadingText` 集中定义段落数量与正文指纹；前端按相同空行规则拆段。

## 接口

均需 Bearer 登录，路径以 `/api` 开头。

| 方法与路径 | 用途 |
| --- | --- |
| GET `/me/bookshelf?page=1&size=12` | 本人书架分页，按收藏时间及作品 ID 倒序；每页上限 50 |
| PUT `/me/bookshelf/{novelId}` | 幂等加入，返回该作品的本人阅读状态 |
| DELETE `/me/bookshelf/{novelId}` | 幂等移出，成功 204，保留进度 |
| GET `/me/novels/{novelId}/reading` | 本人的收藏状态、保存版本及可读恢复位置 |
| PUT `/me/novels/{novelId}/reading` | 保存本人的章节与段落进度 |

保存请求字段：`chapterId`、`paragraphIndex`、`contentRevision`、`version`。初次保存版本 0，后续必须使用读取或上次保存返回的版本。正文指纹直接取公开阅读接口返回值。段落范围还需小于当前正文实际段落数，跨作品章节返回 404。

阅读状态包含 `shelved`、`version`、原记录 `chapterId/paragraphIndex`、安全恢复目标 `resumeChapterId/resumeParagraphIndex`、可读章名 `chapterTitle` 及说明 `message`。前端跳转必须使用恢复目标，不能直接使用失效的原记录。

书架每项包含 `novelId`、上次公开标题 `title`、是否可读 `available`、收藏时间及上述阅读状态。下架条目仅显示此前公开的书名与不可读提示，不返回草稿或正文。

## 前端保存时机与局限

阅读页加载并恢复位置后保存一次；滚动停止约 800 毫秒后保存当前阅读区域的段落；切换路由前等待在途保存并提交最新位置。刷新同章会恢复记录；从目录切换到其他章节时从章首开始。字号与背景继续保存在当前浏览器。

页面隐藏或关闭时尝试以 keepalive 提交，但进程强制结束、断网或设备关机可能使最后一次写入未完成。只有服务端响应成功才显示“已保存”；失败保留提示并提供重试。当前不提供离线进度队列、跨设备实时推送、阅读时长或阅读量统计。

## 人工验收

1. 游客进入作品详情，点击登录后收藏入口；登录后应返回原作品。加入书架后，导航进入“我的书架”。
2. 打开一篇包含多个段落的已审核章节，向下阅读，等待提示“已保存到第 N 段”。
3. 返回书架点击“继续阅读”，应定位到该段；刷新后仍恢复。退出并重新登录，记录仍属于同一账号。
4. 用另一个账号打开书架，应看不到前者收藏及进度。移出后书架条目消失，但作品详情仍可继续上次阅读。
5. 在两个标签页打开同一作品，各自更新进度；旧版本保存应提示冲突，不应悄悄覆盖。
6. 管理员下架章节或作品，再刷新书架核对不可读提示；章节修订审核通过后，恢复到该章开头并提示正文变更。
