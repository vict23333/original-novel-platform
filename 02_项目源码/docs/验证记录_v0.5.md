## 实际 MySQL 检查

首轮实际接口检查发现作者趋势 SQL 使用未引用的 `reads` 别名，与 MySQL 保留字冲突，作者数据接口失败；H2 测试未暴露此兼容问题。修复为引用别名后重新完成后端 67 项测试和打包，补充 40 次实际 HTTP 检查通过。记录该失败，不把首轮全部标记为成功。

验证使用合成账号和临时作品。首次并发上报的两个请求只有一个计数；修复后对已记录身份再次并发上报均不重复计数。游客会话独立计数，收藏/移出改变真实收藏数；作品及章节下架后从榜单移出，不可再次上报。作者只能读取本人数据，空数据为零；草稿修改不影响公开字数和公开更新时间，评论删除同步减少有效评论数量。

21 部原有公开作品的内容响应保持一致。停止并正常重启服务后，对比原作品、临时作品发现数据、评论及作者总览，共 24 个资源响应一致。验收结束后下架 4 部临时公开作品，停用 3 个临时账号，保留内部审计记录；公开书库恢复为原有 21 部，四类榜单各包含这 21 部符合可读条件的作品。

## 可复验步骤与局限

1. 打开首页，组合筛选题材和连载状态，再进入排行榜切换热门、收藏、新书、更新榜。
2. 打开作品详情，查看公开指标、同题材推荐和目录末章入口。
3. 用读者账号阅读一章并刷新，再由作品所属作者查看“作品数据”：当天同一身份只增加一次阅读；没有阅读记录时显示零。
4. 切换其他作者账号，不能访问前一作者的作品数据；管理员下架章节或作品后再次检查公开入口。

统计从功能启用后积累，不补造历史数字；匿名会话和登录账号为不同身份，清除会话可形成新身份，因此不是自然人去重或反刷系统。未做高并发容量、长期运行和生产部署测试。AI 辅助创作、用户管理及分类标签维护仍待实现。接口、指标定义及参考来源见[发现与统计设计](发现与统计设计.md)。
