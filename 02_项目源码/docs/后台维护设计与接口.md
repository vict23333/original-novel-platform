# 后台维护设计与接口

v0.7 补齐 FR-10 用户信息管理、FR-13 分类标签管理，与已有 FR-11 作品审核、FR-12 评论管理共用后台导航。属于原有需求范围，不增加付费、运营活动或账号权限分配模块。本轮交付可验收的维护流程，课程历史提交稿不覆盖。

## 页面入口

| 页面 | 路径 | 用途 |
| --- | --- | --- |
| 作品与章节审核 | `/admin` | 小说、章节审核与违规下架 |
| 用户管理 | `/admin/users` | 查询账号、维护昵称简介、启用停用 |
| 评论管理 | `/admin/comments` | 查询评论与违规删除 |
| 分类与标签 | `/admin/taxonomy` | 维护题材与标签、调整作品归类 |
| 操作记录 | `/admin/audits` | 账号与分类标签维护记录，支持组合筛选与分页 |

管理员从现有登录页登录。首次直接访问具体后台页面，登录后返回来源页；读者和作者无法进入管理页面或调用管理接口。电脑后台提供侧边导航，较窄窗口改为顶部导航；用户、作品列表与编辑面板在 600px 以上并排，手机垂直排列。

## 用户维护规则

- 支持账号/昵称关键词、角色、启用状态与分页查询。接口只返回维护所需字段，不返回密码哈希或令牌版本。
- 修改昵称、简介或账号状态必须填写原因。账号名称、角色、密码不属于本轮修改字段；未知请求字段仍由统一 JSON 配置拒绝。
- 管理员账号只读，包括当前管理员本人，避免误停用导致后台无法进入。管理员自己的昵称和简介沿用个人中心。
- 停用不删除账号、书籍、评论或收藏。作品、评论违规仍分别从内容管理页面处理。
- 状态变更递增 `token_version`；每次鉴权查询数据库状态及令牌版本，旧登录在停用后失效。重新启用也不会恢复旧令牌，须重新登录。
- `admin_version` 用于管理编辑冲突检测。个人中心修改资料也递增该版本，防止后台旧表单覆盖用户的新资料。两条后台写请求先锁定同一账号，再核对版本。

## 分类、标签与作品归类

- 分类和标签名称均为 1—20 字；去除首尾空白，数据库唯一索引拒绝重名。新增、重命名和删除均留操作记录。
- 分类引用统计同时检查小说草稿和已有公开版本；标签统计关联作品数量。被使用的项目禁止删除，须先将所有关联作品重新归类。
- 保留 V2 已有的六种题材及编号，不重建小说或分类。新增分类可直接用于作者新建/编辑作品。
- 每部作品一个分类、最多五个不重复标签。标签由管理员维护和配置，作者自行提报标签不属于本轮实现。
- 待审核作品暂不允许调整归类，先完成审核。其他状态下调整分类会同时更新草稿分类和已有公开分类，标签立即生效；不会发布未审核的标题、简介或正文，也不改变审核/下架状态。
- 归类写入复用小说版本和行锁，递增版本；冲突返回 409，请刷新并重新选择。标签按编号依次加锁，关联写入在同一事务中完成。
- 公开标签接口仅针对已发布且未下架的作品。前台详情页显示标签；标签检索及作者提报标签暂未实现。
- 删除时应用层检查、行锁与数据库外键共同防止悬空引用。底层引用竞争返回 409，不静默级联删除。

## 数据迁移

Flyway V6 新增：`app_user.admin_version`、`novel_category.version`、标签表 `novel_tag`、作品标签关联表 `novel_tag_link`、管理记录表 `admin_audit`。原表字段及业务数据保留。

管理记录包含操作者编号、目标类型/编号、操作类型、原因和 UTC 时间；归类记录包含前后分类与标签编号。不存储密码、令牌或完整个人资料快照。作品审核和评论处理沿用已有独立记录，管理记录接口只读。

## 接口

以下均以 `/api` 为前缀，除公开标签外要求 ADMIN。列表页码从 1 开始，用户每页最多 50 项，归类作品列表固定 12 项。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/admin/users?keyword=&role=&enabled=&page=1&size=12` | 查询用户 |
| PUT | `/admin/users/{id}/profile` | nickname、bio、version、reason |
| PUT | `/admin/users/{id}/status` | enabled、version、reason |
| GET | `/admin/taxonomy/{kind}` | kind 仅 categories 或 tags，含引用数和版本 |
| POST | `/admin/taxonomy/{kind}` | name、version=0 |
| PUT | `/admin/taxonomy/{kind}/{id}` | name、version |
| DELETE | `/admin/taxonomy/{kind}/{id}?version=0` | 仅允许删除未被使用项 |
| GET | `/admin/classification-books?keyword=&page=1` | 按书名查询归类作品 |
| GET | `/admin/novels/{id}/classification` | 获取归类信息和版本 |
| PUT | `/admin/novels/{id}/classification` | categoryId、tagIds、version、reason |
| GET | `/public/novels/{id}/tags` | 已公开作品标签 |
| GET | `/admin/audits` | 最近 50 条维护记录，保留旧接口兼容 |
| GET | `/admin/audits/search?keyword=&type=&action=&page=1&size=12` | 分页检索；可选 targetId 正整数 |

参数校验失败返回 400，未登录 401，角色不符 403，不存在或未公开 404，版本冲突、重名、受保护账号或使用中的分类删除返回 409。

## 验收步骤

1. 用管理员账号登录，进入用户管理，搜索测试账号，修改昵称简介并填写原因；刷新后确认保留。
2. 停用测试账号，用其旧登录操作或重新登录应失败；启用后须重新登录。不要用本人常用账号做停用试验。
3. 新建一个题材和标签，选择测试作品，填写原因并保存归类；已公开作品详情应显示新题材、标签。
4. 已使用的分类和标签不能删除；先将测试作品移出，再删除空项。
5. 查看操作记录；打开两个相同编辑页面分别保存，第二个旧版本应提示冲突。

实际验证结果与已知限制见 [v0.7 验证记录](验证记录_v0.7.md)。
