# 评论互动与内容管理（v0.4）

对应 FR-05、FR-12，并提供作者从作品进入读者反馈的入口。延续需求文档 BR-05：回复统一挂在根评论下，记录被回复对象；删除隐藏正文并保留必要占位。未增加私信、举报、通知或评论预审等需求。

## 页面与业务流程

- 小说详情底部为作品讨论，阅读页章末为本章讨论，两者分开分页。
- 游客可查看；登录后可评论、回复、点赞、取消赞和删除本人评论。作者与管理员也有这些读者能力。
- 评论去掉首尾空白后保存，长度 1—500 字（服务端按 Java 字符串长度校验）；前端按纯文本展示，不解释 HTML。
- 点击回复使用同一编辑框，显示回复对象。回复的回复也放到根评论下，不无限嵌套。根评论按新到旧、回复按旧到新排序，以 ID 保证同一时间的顺序稳定。
- 登录链接保留当前作品或章节地址。网络或业务请求失败时保留编辑框正文；成功后清空并刷新，列表刷新失败不会重新发送已成功的评论。离开页面的未发送评论目前不保存草稿。
- 作者工作台的公开作品显示“查看读者讨论”入口，章节反馈在对应章末查看。汇总统计将在后续 FR-09 实现。
- 管理员从审核页进入评论管理，可按作品编号、正文/昵称/书名关键词及删除状态筛选。删除必须填写原因并二次确认。

## 可见性、删除与权限

发表、查看、回复和点赞都要求作品已公开且未下架；章节评论还要求章节属于该小说，已公开、未删除、未下架。修订待审期间沿用已有公开版本的可见性。跨作品、跨章节或跨作品/章节评论区回复被拒绝。

服务端从 JWT 取得评论人与点赞人，拒绝请求中的额外身份字段。本人删除只允许删除自己的评论；管理删除接口仅 ADMIN 可访问。即使作品下架，本人仍可通过本人删除接口撤回已知评论，管理员仍可处理。

删除清空数据库中的正文，同时记录删除人、原因和 UTC 时间，清除此条评论的点赞。前台、管理员接口均不再返回删除前正文。回复不级联删除，根评论与被回复对象展示“评论已删除”。已删根评论下停止新增回复，但既有有效回复仍可查看、点赞或单独删除。分页总数包含删除占位，不代表有效评论统计值。

## 数据与并发

V4 只新增 `reader_comment` 与 `comment_like` 两表，不改写 V1—V3，也不清空原有数据。

`reader_comment` 记录 novel_id、可空 chapter_id、user_id、root_id、reply_to_id、body、deleted 以及删除审计信息。根评论的 root_id/reply_to_id 为空，回复两项均非空。外键保证目标存在，业务服务保证回复范围与章节归属一致。

`comment_like` 使用 `(comment_id, user_id)` 联合主键。PUT 表示点赞、DELETE 表示取消，不用状态翻转；重复请求保持幂等。写入按作品、章节、评论顺序加行锁，与现有审核下架的锁顺序保持一致。事务显式使用 READ_COMMITTED，避免 MySQL 默认可重复读保留等待锁前的旧点赞快照。该版本将同一作品的评论写入串行化，适合当前演示规模；未据此声称高并发性能。

## 接口

列表返回 `items/page/size/total`，page 为 1—100000，size 为 1—50。公开列表可带登录令牌，以返回本人点赞状态和是否本人评论；无令牌时两项均为 false。

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/api/public/novels/{novelId}/comments` | 根评论分页；可选 chapterId，不传表示作品评论 |
| GET | `/api/public/comments/{id}/replies` | 根评论的回复分页，支持已删根评论 |
| POST | `/api/me/comments` | novelId、可空 chapterId、可空 replyToId、body；201 返回评论 |
| PUT / DELETE | `/api/me/comments/{id}/like` | 点赞/取消赞；200 返回最新计数与本人状态 |
| DELETE | `/api/me/comments/{id}` | 删除本人评论；204，重复删除幂等 |
| GET | `/api/admin/comments` | keyword（最多 100 字）、novelId、deleted 与分页参数 |
| DELETE | `/api/admin/comments/{id}` | JSON reason（1—500 字）；204；保留处理记录 |

错误：400 输入不合法或回复范围不匹配，401 未登录，403 无角色权限或非本人删除，404 目标不存在/已删/不可读。删除原因仅管理员列表可见，公开 DTO 不返回账号、删除人或内部凭据。

## 验收

1. 游客打开作品或章节，能看评论但需登录才能发言、点赞；登录后回到原页。
2. 两个账号在同一评论下回复，回复的回复保持被回复人且不形成多层嵌套。
3. 同一账号重复点赞只有一赞，取消后恢复；另一个账号的点赞互不影响。
4. 删除自己的根评论，正文消失、已有回复保留，其他用户不能删除它。
5. 管理员搜索评论并填写原因删除，前台刷新后只显示占位，后台可查处理原因与时间。
6. 下架作品或章节，评论公开列表与发言/点赞同时关闭。

执行结果见 [v0.4 验证记录](验证记录_v0.4.md)。
