# 创作工作台设计与接口

2026-10-29，v0.13，前后端均为 0.13.0。实现范围为作品总纲/设定、角色卡、本章目标、前文引用预览和上下文起草/续写，另提供规则取名与选段扩写。源于 [升级方案](作者创作工作台升级方案.md)，验收见 [验证记录](验证记录_v0.13.md)。摘要记忆、AI 大纲生成、AI 人设补全、自动审稿及关系图尚未实现。

## 使用路径

作者从“我的作品”的“创作资料”，或作品管理中的“大纲、角色与创作工具”进入工作台。资料页包含“大纲与故事设定”和“角色与取名”两个分区，切换分区保留未保存输入，离开页面会提醒。

章节编辑新增“本章目标与情节安排”。空白正文点击“按本章目标起草”，已有正文点击“承接前文续写”；润色和扩写优先使用选段，否则处理不超过 6000 字符的全文。先准备引用预览，确认将发送的内容后再生成。新章不必先保存即可准备候选，生成不会创建章节记录。采用后仍须保存并送审，空正文可保存但不能送审。

本章目标和正文在同一保存事务、同一章节版本下更新；它也进入本地草稿备份。章目标按稳定章节 ID 保存，调整序号不丢失。旧客户端省略 goal 时保留已有目标；旧本地备份没有 goal 时仍能恢复。

演示账号的《云海铸剑人》仅在新建创作资料为空时补入一份标明“演示设定，可修改”的大纲、规则和两张角色卡，依据既有原创演示内容整理，未改写或送审章节正文。

## 数据与归属

V7 新增三张作者私有表，既有 V1—V6 不修改：

| 表 | 内容 | 约束 |
| --- | --- | --- |
| writing_project | 总纲、世界规则、文风、版本 | novel_id 主键，更新锁定所属作品并检查版本 |
| writing_character | 姓名、别名、身份、人设、版本 | 作品内姓名唯一，每书最多 100 张 |
| writing_chapter_note | 本章目标 | chapter_id 主键，跟随章节保存事务 |

资料仅通过 AUTHOR 接口访问，并校验作品归属；其他作者返回 404，读者/管理员不能使用作者接口。公开书库和正文视图不返回这些资料。管理员章节审核也不返回章目标。维护写作设定不改变作品审核状态或公开版本。

## 引用如何组装

[WritingContext](../backend/src/main/java/com/novelplatform/writing/WritingContext.java) 在短只读事务中构造结构化资料：

1. 作品标题、简介及版本。
2. 全书大纲最多 4000 字符，世界规则最多 3000，文风最多 1000。
3. 作者选择的最多 6 张角色卡，每张人设最多 1000 字符。
4. 最多两章较早的同作品已保存草稿，每章只取末尾最多 2000 字符；预览标明省略数量和来源版本。
5. 当前素材最多 6000、本章目标最多 2000、本次要求最多 500 字符。

前文默认选最近两章，可取消或在最近 50 个较早章节中另选。服务端再次检查作品归属、章节顺序、删除状态和重复条目，不能只信任前端勾选。当前章及后续章节不能作为前文引用。读取作者草稿，不将它混称为读者公开版本。

总输入按序列化后的资料 JSON 长度限制为 32000 个 Java 字符，超过时要求减少资料；核心设定不静默截断。这个数包含格式信息，不是精确 token 数或费用。近章保留的是有界片段，本轮不宣称能够记住整本长篇。

预览返回 SHA-256 指纹。生成前重新组装并比较，外部返回后再组装比较；资料或保存版本变化时拒绝旧结果。外部请求不持有数据库事务。前端编辑正文、目标、章节号或要求后清除旧引用；生成后再改正文或目标时，旧候选不能直接采用。

## 接口

以下路径均以 `/api/author/novels/{novel}/writing` 为前缀：

| 方法与后缀 | 用途 |
| --- | --- |
| GET 空后缀 | 读取创作设定和角色列表；空资料返回默认对象，不写库 |
| PUT 空后缀 | 保存 outline、worldSetting、writingStyle、version |
| POST /characters | 新增 name、aliases、storyRole、profile、version=0 |
| PUT /characters/{id} | 按版本更新角色 |
| DELETE /characters/{id}?version= | 删除指定版本的角色；正文保留 |
| GET /previous?before= | 返回较早章节的 ID、序号、标题和版本 |
| POST /context | 组装预览，不调用模型 |
| POST /generate | 校验预览指纹后发起一次生成，返回候选 |

context/generate 共用输入：chapterId、version（新章可为 null）、chapterNumber、mode、text、goal、instructions、characterIds、previousChapterIds、contextDigest。mode 为 DRAFT/CONTINUE/POLISH/EXPAND。previousChapterIds 为 null 时服务端取默认前两章，空数组表示不引用；界面发送明确选择。generate 必须携带预览的 contextDigest。

预览返回 digest、inputCharacters、payload，payload 包含实际将使用的 task、chapterNumber、goal、authorInstructions、currentText 和 sources。生成返回 content、truncated、model，复用原有结果结构。现有章节级 `/api/author/chapters/{id}/ai` 保持兼容，当前界面使用新流程。

## 生成与本地工具

[WritingAiService](../backend/src/main/java/com/novelplatform/writing/WritingAiService.java) 复用 AiLimiter 和 AiGateway；供应商凭据仍只从后端配置读取。不同任务有各自写作要求，但不引入新 Agent 框架、模型依赖或向量数据库。结果仍是可编辑候选；失败、超时或过期不会修改服务器正文。

引用预览不收费，点击“确认资料并生成候选”才调用外部服务。不会在续写后自动总结、审稿或写下一章，也不会自动重试失败请求。关闭页面只会取消客户端等待，不能保证已发出的供应商请求停止计费。

[nameTools.js](../frontend/src/nameTools.js) 使用本地字库组合候选，支持现代/古风/幻想人名，以及地名、组织名。每次最多 12 个、界面默认 8 个，排除本书已保存的角色名。人名填入表单后仍需主动保存；其他类型可复制。它是规则工具，不是 AI，也不代表名称在全网唯一。

## 验证与当前限制

本轮 117 项后端测试、48 项前端测试、生产构建、36 次 MySQL HTTP 检查以及 Edge 首批工作流通过，详见 [验证记录](验证记录_v0.13.md)。AI 生成部分使用隔离模拟供应商验证请求与保护机制，没有额外调用 DeepSeek。先前两次真实联调属于旧章节级流程，不能作为新上下文流程的质量证明。

目标、总纲和角色卡可以人工维护；自动生成大纲、人设、章节摘要、长期记忆、设定审查仍在后续批次。生成片段有长度上限，不承诺一次写完完整长章。未发布测试作品保留，测试章节已软删除、临时账号停用；公开书库仍为原有 128 部。
